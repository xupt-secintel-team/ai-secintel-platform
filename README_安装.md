# AI-SecIntel 2.3 · 安装与启动

> 一份给"拿到包的人"看的说明。三件事：装环境、放语料、起服务。
>
> ⚠️ **本包不含语料**：装完环境后，请先跳到 [四、语料（数据）](#四语料数据) 把语料放到位，
> 否则执行启动脚本时会提示未找到语料并退出。这是唯一一个必须联网（或拷贝现成语料）的步骤。

---

## 一、三种系统的安装方式

| 系统 | 双击这个 | 或者命令行 |
|------|----------|-----------|
| Windows 7 / 8 / 10 / 11 | `安装.bat` | `python bootstrap.py` |
| macOS 10.13+ | `安装.command` | `./安装.sh` |
| Ubuntu / CentOS / Debian | — | `./安装.sh` |

安装程序会依次做：

1. **环境体检** —— Python 版本、操作系统、CPU、内存、磁盘，得出性能档位
2. **建虚拟环境** —— 项目内 `.venv`，不污染系统 Python
3. **自动选源** —— 并发探测清华 / 阿里 / 腾讯 / 中科大 / 官方源，挑最快可达的
4. **按档装依赖** —— 低配只装核心档，高配才建议 torch（见下表）
5. **安装后自检** —— 逐个 import 验证，写 `.aisec_env.json` 环境档案

### 依赖分档（为什么要分档）

torch 装机约 470MB、transformers 再 200MB+，在 4GB 内存的机器上装完就占满磁盘、
启动还要多十几秒；而它只影响"新建语义索引"这一个可选功能（已有索引照样能检索）。
所以：

| 档位 | 判定条件 | 安装内容 |
|------|----------|----------|
| low 低配 | CPU ≤ 2 核 或 内存 < 4GB 或 磁盘剩 < 2GB | `requests` `urllib3` |
| mid 主流 | CPU ≤ 4 核 或 内存 < 8GB | + `beautifulsoup4` `numpy` |
| high 高配 | 其余 | + `openai`（torch 需 `--full` 显式确认） |

想强制装全套（含本地嵌入模型）：

```bash
安装.bat --full        # Windows
./安装.sh --full       # macOS / Linux
```

离线机器（不联网）：

```bash
安装.bat --offline     # 只检测，不装包；功能自动降级
```

## 二、启动

| 系统 | 双击 | 命令行 |
|------|------|--------|
| Windows | `启动服务.bat` | `python core/server.py 8848` |
| macOS | `start.command` | `./start.sh 8848` |
| Linux | — | `./start.sh 8848` |

启动后打开控制台：**http://127.0.0.1:8848/**

首次运行会自动触发环境配置（无需先跑安装）；之后直接启动。

## 三、慢机器怎么用（重点）

系统开机时会先给这台机器"画像"，再据此统一缩放参数，不需要手工调：

```
环境画像：Windows AMD64 / CPU 8 核 / 内存 31.6GB / 可用磁盘 22.2GB
性能档位：high（高配）（自动判定）
生效策略：超时 ×1.0 · 并发上限 8 · 预热查询 6 条 · 语义模型预热 开
```

低配档（low）会自动生效的策略：

| 项目 | 高配 | 低配 | 原因 |
|------|------|------|------|
| 网络超时 | ×1.0 | ×2.0 | 慢机器网络/磁盘都慢，超时不放大必然误判失败 |
| 并发上限 | 8 | 2 | 并发换不来速度，只会把单核压满导致整体更慢 |
| 语义模型预热 | 开 | 关 | torch 加载约 470MB、16s，慢机器上白占资源 |
| 快车道轮询 | 15s | 60s | 后台轮询是慢机上最容易被忽略的隐形负载 |
| 自动增量同步 | 5 分钟 | 关闭 | 单轮含加载 267MB 语料，慢机上会持续重叠 |
| 图谱默认跳数 | 2 跳 | 1 跳 | 多跳遍历在慢机上明显卡顿 |
| 预热查询条数 | 6 条 | 2 条 | 预热是为了首屏快，但本身也要花时间 |

手工强制档位（比如评审现场要临时降档）：

```bash
export AISEC_PERF_TIER=low     # macOS / Linux
set AISEC_PERF_TIER=low        # Windows cmd
./start.sh --low               # 或者直接加参数
```

查看本机画像：`python core/envprofile.py`（加 `--json` 输出机器可读）。

## 四、语料（数据）

> ⚠️ **本安装包不含语料。第一次启动前必须先完成本节，否则服务会拒绝启动。**

语料库 `data/corpus.json` 约 274MB、索引缓存 286MB，**不打进安装包**（否则包体 1.8GB+，解压就要十几分钟）。
两种获得方式，任选其一：

1. **联网抓取**（推荐，装完直接跑）：

   ```bash
   python core/fetch_corpus.py
   ```

   抓取耗时视网速而定（通常十几分钟），完成后会在 `data/` 下生成 `corpus.json`。

2. **拷贝现成语料包**：把现成的 `data/` 目录放到项目根目录下即可
   （至少要有 `data/corpus.json`；索引缓存 `corpus.json.idxcache` 缺失时会自动重建，仅首次启动慢一些）。

没有语料时，启动会打印上面的获取命令后退出（**不会**静默失败，也不会进入无数据的空界面）。

## 五、常见问题

**Q：双击 bat 一闪而过？**
A：多半是 Windows 控制台代码页（GBK）打印中文时抛了异常。系统已内置 UTF-8 兜底；
若仍闪退，在 cmd 里手动执行 `python core/server.py 8848` 看真实报错。

**Q：提示端口被占用？**
A：按提示里的命令查占用进程。注意 Windows 用 `netstat -ano | findstr :8848`，
macOS 用 `lsof -nP -iTCP:8848 -sTCP:LISTEN`，Linux 用 `ss -ltnp`——
系统给出的提示会自动匹配当前平台。换端口：`启动服务.bat 8899`。

**Q：装依赖一直卡住？**
A：是软件源不可达（国内机器连 pypi.org 经常 30s 超时）。安装程序会自动测速改走国内镜像；
若仍失败，手动指定：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

**Q：没装 numpy 会怎样？**
A：语义向量检索降级为纯关键词检索，功能完整、召回略弱。**不会崩**——这是设计好的降级路径。

**Q：Python 版本低于 3.7？**
A：安装程序会拒绝并给出对应系统的安装命令。Python 2 明确不支持。
下限卡在 3.7 是因为代码用了 `from __future__ import annotations`（41 个文件）
与 `dataclasses`，这两样都是 3.7 才有的。

## 六、为什么最低要 Python 3.7

| 依赖 | 引入版本 | 用在哪 |
|------|----------|--------|
| `from __future__ import annotations` | 3.7 | 41 个文件的类型注解 |
| `dataclasses` | 3.7 | m2_enrich 资产 / POC 数据结构 |
| f-string | 3.6 | 全项目 |
| dict 保序 | 3.7（语言规范） | 检索结果排序、缓存键 |

3.7 可安装于 **Windows 7 SP1+ / macOS 10.9+ / Ubuntu 14.04+**，
完整覆盖"2012 年以后的操作系统"。3.7 上缺失的少数 3.8/3.9 API
（`cached_property`、`importlib.metadata`、`str.removeprefix`）
由 `core/compat.py` 兜底补齐，所以主流程在 3.7 上不降级。
