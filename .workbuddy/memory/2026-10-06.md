## 未读角标（rail-badge）修正 + 删订阅提示

用户问「为什么没角标」→ 实测后端 `unread=3, subs=1` 但界面无角标。根因两条，都不是后端问题：

1. **角标只在页面加载时算一次，之后每 45s 轮询**（app.js initSubBadge）。
   用户在面板里新增/巡检/全部已读/删除订阅后，侧栏红点最多要等 45 秒才跟着变，
   用户会以为「功能没生效」。这是真实的时序缺陷，不是错觉。
2. **判据只有 `unread > 0`**，删光订阅后历史未读还在 → 红点永久挂着，
   容易被当成"漏看了消息"。

### 改动
- `frontend/app.js` `initSubBadge()`：
  - `paint(n, subs)` 双参，**`subs === 0` 时不画角标**（用户需求）
  - 暴露 `AISEC.refreshSubBadge = tick`，供模块在改动订阅数据后立即重算
- `modules/m2_enrich/web/panel.js`：
  - `refresh()` 里调 `AISEC.refreshSubBadge()`，消除 45 秒延迟
  - 删除订阅加 `confirm()` 二次确认，文案按该订阅**自己的**未读数给
    （`unreadBy[sub_id]` 按 sub_id 聚合，不能用全局 unread，否则会吓到用户）
  - 后端返回 `ok=false` 时不再无条件 toast「已删除订阅」——原来不看返回体的写法
    会在删除失败时也报成功

### 踩坑（写测试时犯的，别重复）
- `add.body.sub || add.body.id || ...` 取 id：`sub` 是**对象**，JS 里永远 truthy，
  于是 sid 变成对象 → 删除接口收到 `{}` → `deleted=0`，看起来像后端删不掉。
  必须显式 `.id`。用 Python 复现时 `or` 短路同理。
- `console.log('%d', x)` 在 Node 里不成立（Node 的 util.format 不认 %d），
  要用模板串。第一版测试因此打出 `subs 从 %d 变成 %d`。
- 测试失败留下的探测订阅**会留在真实数据里**（这次是 `__probe_zzz__`），
  跑完必须清理，否则用户下次看到莫名订阅。e2e 脚本应自带 cleanup。

### 测试
- 新增 `tools/_test_sub_badge.js`（19 项 DOM 桩）：正常/订阅为 0/反向移除/四种异常响应/
  网络 reject/99+ 上限 + 模块侧文案与判据静态检查
- 新增 `tools/_e2e_sub_badge.js`（11 项真实 HTTP）：subs 字段确实是数字、
  增删订阅往返、历史告警不被误删、静态资源已带新逻辑

## 大文件上传 Failed to fetch —— 根因定位与修复（本日最难的一个 bug）

### 症状
上传 122MB / 688MB 的 CMDB `.db` → 浏览器 `Failed to fetch`，e2e 报
`RemoteDisconnected: Remote end closed connection without response`。
服务端**无任何 traceback**，日志只到 `analyze done ok=True`，永远等不到响应写出。

### 排查路径（关键教训：插桩要打在 finally 前后）
前几轮插桩（`dispatch start/done`）只能证明"dispatch 没返回"，无法定位。
**把插桩打进 `finally` 内部的 `_cleanup_sqlite_uploads` 之后，断点立刻收敛到一行**：
```
[diag] analyze done ok=True
[diag] cleanup start exists=True p=...\xxx.db
   ← cleanup done / cleanup FAILED 都没打印
```

### 真正的根因（两层）
1. **表层**：`handle_cmdb_scan_post` 的 `finally` 里**同步** `os.remove` 122MB 临时库，
   清理阻塞 → 响应永远写不出去 → 客户端断连。
2. **底层**：本机 WorkBuddy 通过 `sitecustomize.py`
   （`.../cli/vendor/shim/sitecustomize.py`，由 PYTHONPATH 注入）
   把 `os.remove` / `os.unlink` 换成了 `_safe_remove` —— "移入回收站"实现
   （fork `genie-trash.exe` 或 `SHFileOperationW`）。
   **这条路径在几百 MB 文件上会长时间不返回。**
   注意 `os.unlink is os.remove`（CPython），所以换用 unlink 毫无用处。

### 排除的干扰项（都验证过，别再走一遍）
- 不是文件锁：外部进程 0.19s 就能删同一个文件
- 不是文件大小：主线程/子线程、88MB~305MB 梯度测试全部 0.13~0.16s
- 不是客户端超时：e2e timeout=1800s
- 不是 gzip / json.dumps / 响应体积（已从 604MB 修到 0.86MB）
- 不是 sqlite 句柄未关（那会 0.00s 立刻抛 PermissionError，不是挂起）

### 修复（`modules/m2_enrich/api.py`）
- 新增 `_hard_unlink()`：Windows 下直接 `ctypes` 调 `DeleteFileW`，
  **完全绕开 Python 层包装**。305MB 实测 **0.04s**；占用时按
  ERROR_SHARING_VIOLATION(32)/ACCESS_DENIED(5) 退避重试 6 次。
- 新增 `_cleanup_sqlite_uploads_async()`：守护线程删除，入口 **0.02s 立即返回**。
  清理是 housekeeping，**绝不能阻塞响应**。
- `_delete_temp_db()` 保留"必须在 tmp_cmdb 目录内"的防误删校验。
- `finally` 与三处流式回滚全部改用异步版。
- 顺手补 `import sys`（新代码用到了，原来没导入，会在运行到删除时才炸）。

### 顺带补齐的半成品
`modules/m2_enrich/web/panel.js` 里 `postWithProgress` / `downloadBlob`
**被调用但从未定义**（上传进度功能是坏的，一走就 ReferenceError）。
补齐时还发现 `hdrs` 在用之后才 `const` 声明 → 同样 ReferenceError，一并修好。

### 复现/回归
- 单元：6 项（普通/幂等/305MB 大库/目录外拒绝/异步非阻塞/异步真删）全 PASS
- e2e `tools/_e2e_cmdb_bigfile.py`：HTTP 200、ok=true、报告内容自洽、413 文案、
  临时文件无残留 —— 全部 PASS

### 修复后暴露的第二个 bug：临时文件同秒撞名 → Permission denied
异步清理上线后，`_e2e_cmdb_sqlite_upload.py` 的「混入坏库」用例开始 400：
```
数据库文件写入临时目录失败：[Errno 13] Permission denied: ...tmp_cmdb\1791264328_43192_00_01_ledger.db
```
根因：**两个落盘函数各自算秒级戳**。
- `_stage_sqlite_uploads()`（小库 / base64 路径，8KB 样本走这里）
- `_stage_sqlite_uploads_stream()`（大库 / 流式路径）
都是 `stamp = "%d_%d" % (int(time()), pid)`，同一秒内先后上传算出**完全相同**的路径。
清理改异步后残留窗口更大，从"理论可能"变成 e2e 稳定复现。

修法：抽 `_unique_stamp()`（毫秒 + 进程内 `itertools.count()` 序号），两处共用。
新增测试 ⑨ 锁住这个不变量：连打 500 次不撞名 + 静态检查"两个落盘点都走它、没有残留秒级写法"。

### 踩过的两个坑（重要，别再犯）
1. **对着陈旧进程做测试**：旧实例占着 8848，新实例启动即退出（"端口已有服务在监听"），
   但 `/api/health` 照样有响应 —— 看起来是新代码在跑，其实连的是旧进程，
   修复根本没被验证。**每次重启后必须核对 `netstat` 里的 PID 变了**。
2. **测试自身用 `os.remove` 卡死**：测试脚本删自己的临时文件时同样被 shim 包装，
   卡住后导致后面所有断言连环失败，看起来像服务端坏了。
   已给 3 个测试加 `hard_remove()` / 复用 `api._hard_unlink`。

### 最终回归
- Python 27 个测试文件：全通过（`_test_cmdb_bigfile` 23 项、`_test_report_size` 19 项、
  `_test_find_record_cache` 13 项）
- JS 6 个测试文件：全通过
- `_e2e_cmdb_bigfile.py`（122.6MB 真实库）：全部通过
- `_e2e_cmdb_sqlite_upload.py`：全部通过
- `[diag]` 插桩已全部清除；`core/registry.py` 无 `_spill_path` 残留

## ① 修「明明有网却报网络中断」—— file 模式没有流式路径（本日第二个根因）

### 症状
上传 10 个 xlsx（共约 374MB）→ `分析失败：网络中断，请检查连接后重试`。
用户原话："明明有网"。

### 复现（40MB 单文件即可稳定复现）
```
EXC ConnectionAbortedError [WinError 10053] 你的主机中的软件中止了一个已建立的连接
```

### 根因（与 688MB 那个 os.remove 阻塞是**完全不同的两件事**）
`core/server.py` 对 >32MB 的请求体走 `begin_stream()`，此时 **`req.body` 是空的**
（内容留在 socket 流里）。但 `handle_cmdb_scan_post` 的分流条件写的是：
```python
if mode == "sqlite" and hasattr(req, "iter_body") and not req.body:
    ... 流式切分 ...
else:
    body_bytes = req.body or b""      # ← file 模式落到这里，拿到空字节
```
于是 file 模式：拿到空 body → 立刻返回 400「文件清单与请求体大小不符」→
**服务端此时已经开始写响应并关闭连接，而浏览器还在往 socket 写 374MB** →
客户端收到 WinError 10053 → XHR `onerror` → 前端只能显示「网络中断」。
**真实错误信息（清单不匹配）被完全掩盖**，所以用户查不到原因。

### 修法
1. 把流式切分逻辑抽成通用函数 `_stage_manifest_stream(req, mfiles, name_fn, hint)`，
   sqlite 与 file 两条路径共用（原来只有 sqlite 有）。
2. file 模式也走流式落盘，落盘后由新的 `_file_entries_from_paths()` 返回
   **惰性序列**：实现 `__len__` / `__iter__` / `__getitem__` / `release_one()`，
   每个文件解析完立刻释放其字节 → **峰值内存 = 单文件而非全部之和**。
3. `cmdb_scan.py` file 模式：
   - 去掉 `list(cfg.get("files"))`（会一次性拉全量）与 `[f for f in files if f.get("data")]`
   - **把 `_build_loc_index(files)` 挪到 `_parse_file_worker` 之前**——
     两阶段都要遍历全部文件，先建索引才能在解析阶段复用/释放字节；反过来要缓存全部。

### 验证
51MB / 6 个 xlsx → HTTP 200，29 秒完成，报告内容自洽。
新增回归测试 ⑩（15 项，tools/_test_cmdb_bigfile.py，共 43 项全通过）。

### 踩坑
`_stage_manifest_stream` 的 `hint` 参数我最初传了 1 元组，格式串却用 `hint[1]`
→ 截断时报 `tuple index out of range`，把"上传被中断"这个真实原因掩盖成
看不懂的崩溃。**变长参数结构必须在定义处就校验长度**，别指望调用方记得。

## ② 新功能：分析后把报告发到邮箱 + 简略版处置台账

### 用户需求
1. 分析 CMDB 之前可以选择把报告发送给输入的邮箱；
2. 参照客户提供的《SVMS_TKT_06_OCT 1.xlsx》出一份**简略版报告**，
   **原有的不删**，用户可以选择下载哪一份；
3. 两个版本可自动发给不同的邮箱。

### 参考模板的结构（读完 xlsx 得出）
- Sheet1：风险等级透视（Risk Level × Count）
- Sheet2：责任人 × 风险等级 × 处置阶段（Survey of Countermeasures）× 三步期限
- Page 1：77 列完整台账
→ 核心是「**谁、什么时候之前、做什么**」这条主线，推导过程反而是次要的。

### 新增文件
- `modules/m2_enrich/backend/mailer.py`：纯标准库 smtplib（不引第三方包）。
  收件人解析（`,;，；、` + 空白分隔、尖括号、去重）、MIME（中文主题 Header 编码、
  纯文本+HTML 双备选）、错误文案可操作（认证失败提示"QQ/163 填授权码不是登录密码"）。
  **外发默认 `mask=basic`** —— 报告含责任人邮箱/内网 IP，直接发原文是安全事故。
  `attach_md` 默认 **False**（正文已是完整报告，附件是可选的）。
  `send_async()` 走守护线程 —— SMTP 最多阻塞 30s，绝不能让用户干等。
- `modules/m2_enrich/backend/cmdb_ticket_xlsx.py`：简略台账导出，4 个 sheet
  （风险等级统计 / 按责任人分派 / 工单明细 / 说明），18 列。

### 关键设计：两个版本**并存不互斥**
| | 简略台账 xlsx | 七章制 Markdown |
|---|---|---|
| 用途 | 日常派单、按人分发、填进客户既有台账 | 评审、归档、追溯"为什么判这个等级" |
| 入口 | `GET /api/cmdb_scan/tickets` | `GET /api/cmdb_scan?id=..&md=1`（原有） |

### 简略台账的两个数据兜底（缺任责人会让这张表失去意义）
1. **责任人**：工单没带 `owners` 时，按 `hosts` 去报告 `meta`（CMDB 台账）反查 owner。
2. **去重**：历史报告里同一 (CVE, 组件) 会重复多行。但去重键**必须带 asset_count** ——

## 验收补强第 2 轮：运维可观测性（日志轮转 + 指标告警）

### 新增文件
- `core/logrotate.py` —— 按大小轮转 + 保留 N 世代。默认 8MB × 5 份（约 48MB/文件）。
- `core/metrics.py` —— 磁盘/内存/CPU/实时流存活/HTTP 时延与错误率 + 阈值告警，
  带 Prometheus 文本导出。纯标准库（**刻意不装 psutil**，避免四处依赖同步）。
- `tools/_test_ops_observability.py` —— 54 条断言，钉死本轮全部能力。

### 轮转的三个坑（都是自己写出来又被测试抓回来的）
1. **`_shift()` 只搬 `.1/.2`，从没把当前文件移到 `.1`** —— 等于每轮原地重建，
   写 20800 字节而阈值只有 2048，完全不轮转。
2. **`write()` 按 `_written+nb>max` 判断，`_reopen()` 又按 `_size>=max` 自判一次** ——
   两个条件不等价，触轮转时文件其实还没到 max（4050/4096），`shift` 压根没被调用，
   文件越过阈值继续长（实测 4100、198）。**轮转决策必须只留一处**。
3. **`max_bytes = max(1024, int(x))`** 会把用户显式配的小阈值静默抬到 1MB
   （传 100 变 1024）。配置被静默改写是最难查的一类问题。
- 另外：`newline="\n"` 必须显式给，否则 Windows 下 `\n→\r\n` 让字节记账逐行漂移；
  单笔超上限要截断 + 标注（不能只靠切分），且标注行本身也要算进预算。

### Windows 上轮转不能靠 Popen(stdout=句柄)
`os.replace` 搬不动被子进程继承的句柄。已改为 **管道 → 父进程 log-pump 线程 →
RotatingLog**，父进程独占写入权。
`tools/watchdog.py` 的日志同样接了轮转，并保留裸 append 兜底。

### 指标采集的两个平台坑
- **`os.statvfs` 在 Windows 不存在** → 磁盘指标恒为 null，改用 `shutil.disk_usage`。
- **ctypes 调 `K32GetProcessMemoryInfo` 必须显式声明 `restype/argtypes`**，
  否则 `WorkingSetSize`（64 位 size_t）被按 4 字节猜传参，RSS 恒为 None
  （实测声明后 37.7MB，不声明恒 None）。
- **`/proc/self/stat` 不能直接 `split()`**：第 2 字段 comm 可能含空格
  （`(my long app name)`），必须 `rsplit(")",1)`，否则后续字段整体错位。
  rsplit 后 utime/stime 是**索引 11/12**（用权威字段表核过，别再手数）。

### 告警设计原则：宁可漏报，不可误报
"采集线程已消失"只在 `ever_polled=True` 时判定 —— 否则任何独立跑 `metrics.py` 的
场景都会常年报 critical。**告警疲劳等于没有告警。**
同理，`/api/health` 只在 critical 时把 ok 拉低，warn 不影响。

### 靠猜线程名必被自己的代码打脸
第一版判 `th.name.startswith("live-poll")`，而 `modules/m1_monitor/api.py` 里
真实是 `name="live"` → 对着真服务也报"线程已消失"。已改为 `_LIVE_THREAD_NAMES`
白名单，并加测试**真读 api.py 源码比对**，改名漏改会立刻红。

### `/api/health` 此前是"假健康"
无论磁盘满、采集线程死都恒返回 `ok: true`。现并入 `alert_level`，
critical 时置 `ok: false` + `status: "degraded"`。
`/api/metrics` 放在 `get_engine()` **之前** —— 监控端点不能被冷启动的语料加载阻塞。

### 前端
`modules/m0_ops/web/ops.js` 加「基础设施指标与阈值告警」区块（8 个指标 tile +
告警条含处置建议），`ops.css` 加 `.ops-mt-*` 样式（走既有 CSS 变量，明暗适配）。
`refresh` 已导出给 `tools/_test_ops_panel.js`（新增 21 条断言，51/51）。

### 踩到的坑（都实测复现过）
- **同一篇文章重复 162 次**：CrowdStrike 分页抓取导致 URL 后缀不同、id 也不同，

  拼进 class 变 `"[object Object]"`；`constructor`/`toString` 同理。
  改用 `Map` + 小写归一（后端给小写，但 NVD 原文可能是 `'CRITICAL'`，
  不归一化会全落 info，看着像"今天全是资讯"）。
- **`javascript:` 链接**：日报 link 来自 54 个外部源，直接进 `href` 就是 XSS。

文件头写着"模块契约一个都没动，别改"。日报要出现在监测台，
**没有加新钩子进契约**，而是照 `enrichSections` 的既有模式：
主体 `renderMonitor` 末尾加 5 行 `AISEC.collect('monitorSections')`，
模块提供 `{id, html, mount}`。这是**扩展**既有机制 —— 没实现该钩子的模块
什么都不发生，老模块整包替换不受影响。

### 自动生成
- 启动后延 8s 生成一份（否则 `--no-live` 时今天永远没日报）
- 快车道轮询有新增时检查一次，**同一天最多每小时重算一次**（`_GEN_MIN_GAP=3600`）
- 清理每天一次
- 实测 collect 72ms + xlsx 753ms ≈ 0.5s/次，节流判断只看一次 `os.stat`

### 保留期的一个设计决定
被清理的日期记进 `_expired.json`。否则页面查 40 天前只会显示"没有报告"，
分不清是"那天系统没跑"还是"已过保留期被清了"。
**不造占位的假报告文件** —— 那会让"这天有报告"变成误导。

### PDF 生成踩的四个坑（都写进 build_pdf.py 注释了）

1. **Consolas 没有中文字形** → 代码块里的中文注释**全部消失**（13 个代码块全中招）。
   修法：`_mono_markup()` 做 run 级混排 —— ASCII 走 Consolas 7.0pt，
   中文走微软雅黑 **7.7pt**（= 2 个 Consolas 半角宽，实测 2×0.5498em），
   这样框线图才对得齐。**不能用 `Preformatted`**：它只能一个字体。

2. **不能用"单列多段落"判代码块**。封面的「系统规模」信息框也是单列多段落，
   误判成代码块 → Consolas 无中文字 → **封面中文整块变空白**（pypdf 只提取到数字）。
   正确判据是**底纹色**：`F4F6F9`=代码块 / `EAF1FB`=提示框 / 无=封面框。
   （`docx_engine._shade` 已经打了底纹，直接读 `w:tcPr/w:shd/@w:fill`）

3. **目录里的章节名和正文标题长得一模一样**（都是 "1.1 xxx"），
   不隔离出来会被 `_head_size` 判成真标题 → 每个都触发 `PageBreak` →
   **目录散成 10 页**。边界不能用"下一个 `第 1 章`"（目录自己第一条就是它，
   区间会缩成 0 行），要用**正文前的显式分页符段落**（`_has_page_break`）。
   另外目录条目有**前导全角空格 U+3000**，`^\d+\.\d+` 锚定失败，
   必须先 `_strip_indent()`（`.lstrip("　 \t·")`）。

4. **KeepTogether 不能放进 Table 单元格** —— reportlab 会算出 16777223pt
   的假高度并抛 `LayoutError: too large on page`。单元格内始终放 Paragraph 列表，
   KeepTogether 只包外层的 `[Spacer, Table, Spacer]`。

5. **表格列宽不能按 `len()` 分配**。中文字符数少但渲染宽、英文数字多但渲染窄，
   导致「语料条目数」(5 字) 分到的列比「① AI基础设施与推理框架」(13 字符) 还宽，
   首列被折成两行。改成 `_vis()`（中文按 2 计）+ `_col_widths()` 夹逼分配，
   首列保底 3.6cm。
