## 修复：顶栏日期显示异常（用户报障：只显示「2026-09-」且被截断）

**根因（3 条）**
1. **数据口径错**：顶栏第 4 格显示 `meta.generated_at`（语料快照生成时间，写死在 stats 文件里 = 2026-09-24），语料不重建就永远停在那天。真正的新鲜时间是 `meta.monitored_at` / `meta.monitor.last_sync`。
2. **样式截断**：`.top-stat{overflow:hidden}` + `.kv{white-space:nowrap}`，长文本 `2026-09-24 16:52 采集` 空间不够时从右往左被裁成「2026-09-」。且 `<1400px` 的降级规则 `.kv:nth-child(n+5)` 早已失效（v11 H1 后只剩 4 格）。
3. **格式脆弱**：`.replace('T',' ').slice(0,16)` 字符串硬切，无 Date 解析、无时区归一。

**修复（frontend/app.js + styles.css，缓存号 v=26/v=21）**
- 新增 `fmtFresh(iso)` + `updateFresh()`：`monitored_at → monitor.last_sync → generated_at` 逐级兜底；`new Date()` 解析 ISO（带 offset，自动归一到用户本机时区，Chrome/Firefox/Safari 均安全）；按 今天 `HH:mm` / 昨天 `昨天 HH:mm` / 今年 `MM-DD HH:mm` / 跨年带年份 分级显示；`setInterval(updateFresh, 60000)` 跨天自动切口径；>36h 未同步 `.kv.fresh.stale` 绿点变琥珀（--warn）。
- title 悬浮显示完整本地时间 + 语料快照生成时间。
- CSS：`.top-stat .kv.fresh{flex:none;display:flex}` 不再被裁；`<1400px` 改为 `.kv.fresh{display:none}`（日期格最先让位，三数字格保住）。

## v12.2 修正：卡顿 / 切视图卡死 / 浅色隐形 / 顶栏不居中（用户报障 4 连）

**根因**
1. 卡顿主因：v12 给常驻大件 .viewhead/.searchbar 加了 backdrop-filter，底下是每帧都在动的全屏 WebGL 画布 → 浏览器每帧对所有毛玻璃区域重新采样模糊（合成风暴）。次要：DPR 1.75 + antialias + 920 粒子、pointermove 每次 getBoundingClientRect 强制同步布局。
2. 切视图卡死：fx.js 降级判据是「4 秒累计窗口 fps」，切视图的大块 innerHTML 重绘 = 主线程长任务，把窗口 fps 拉穿 <20 → degraded=2 → return 永久停循环（必须刷新）。降级是单程票，无恢复。
3. 浅色隐形：粒子是金/玉亮色 ×(.45~1)，白底上普通混合仍接近隐形；线框 opacity .07~.10 也看不见。
4. 顶栏数字：.top-stat .kv 是 text-align:right。

**修复（frontend/fx.js v2 重写 + styles.css v=28 + index.html fx.js?v=2）**
- fx.js：DPR≤1.5、antialias 关、粒子 ≤640；降级改为逐帧 EMA（>250ms 单帧=长任务丢弃不计），分级 0 全量→1 半粒子→2 半粒子+隔帧(30fps 上限)，永不停循环，帧耗恢复可逐级回升；暴露 window.__fxStats{frames,degraded,ema} 供点检；sheen pointermove 改 rAF 节流；浅色主题粒子换压暗色板（深金 .55,.38,.10 / 深玉 .06,.48,.38）+ NormalBlending opacity .62，线框两档透明度（深 .07~.10 / 浅 .22~.30）。
- styles.css：撤 .viewhead/.searchbar 的 backdrop-filter（回 v11 近实心），瞬态浮层模糊半径统一下调一档（18→12 等）；浅色 #fxgl opacity .5→.9；.top-stat .kv text-align:center。
- 注意：v11 遗留的 backdrop-filter（cmdbar blur18/inspector blur14/resbar blur4 等）未动——那是旧设计且用户此前无感。

**★ 教训（已同步 MEMORY.md）**
- 同一条消息里对同一文件发多个 Edit 会静默丢改动（本次 3 个 Edit 丢了 #fxgl 那处；_fx_verify.py 也丢过 1 处）→ 同文件多处修改必须串行 + 改后 grep 验证落盘。
