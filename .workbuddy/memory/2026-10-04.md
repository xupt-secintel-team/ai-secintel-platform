## 公司 CMDB 连接功能（富化板块"资产风险体检"下方新增，2026-10-04 完成）

用户需求：接口连公司 CMDB，自动分析资产风险/脆弱性，出报告（优先修什么/怎么修/怎么检查已修复），可下载文件。

### 实现
- 新增 `modules/m2_enrich/backend/cmdb_scan.py`：三种接入模式（rest 直连 / inline 粘贴 JSON·CSV·TSV / file 上传），复用 asset_scan 的 CPE 版本区间判定 + remediation 的修复方案。
- `api.py` 注册三个接口：`POST /api/cmdb_scan`（分析）、`GET /api/cmdb_scan`（历史/?id=/?md=1）、`GET /api/cmdb_scan/config`（配置状态，不下发密钥）。
- 前端 `web/panel.js` 新增 ACMDB 区块，插在 ASCAN（资产风险体检）之后；panel.css 加 cm- 前缀样式。

### 大数据量加固（100 万 CI 能扛）
- **结构化快速路径** `_structured_extract`：CMDB 记录是 dict，直接用字段值构造资产 + 经 `_PRODUCT_DICT` 映射到语料规范 CPE 名，跳过正则扫描。**30 万条从 81.2s 降到 4.94s（16 倍）**，10 万条端到端 2s。
- 生成器流式（`iter + islice`），meta 截断到 10000 条，上限保护 MAX_CI=100 万 / MAX_PRODUCTS=10 万。
- 报告截断：hosts/products 明细只带前 200，其余进 summary 计数 + scale 字段。

### 关键坑（本项目）
- `_chunked_extract` 早期用 `len(rows)` + 切片，不支持生成器 → 改 `iter + itertools.islice` 流式。
- 30 万条曾 SIGTERM：meta 累积 30 万个 dict 是内存大户 → 截断到 10000。
- 结构化快速路径的正确性关键：产品名必须经 `_PRODUCT_DICT` 映射到规范 CPE 名（如 "Apache HTTP Server"→"http_server"），否则 scanner 匹配不到。
- 语料真实产品名是带下划线 CPE 格式（http_server/vllm/n8n/langflow/flowise/mlflow 等），AI 框架覆盖已很全。

## CMDB 功能复查优化（2026-10-05 凌晨）

对 cmdb_scan.py 做了一轮性能复查，识别并修复 4 处：
1. `_find_record` 原每次全量线性扫 engine.docs（10 万+条），优先清单前 10 条各扫一次 = 百万次比较 → 加 `_ID_INDEX_CACHE`（按引擎代际缓存 id→doc，同 asset_scan 的 _INDEX_CACHE 思路），首次建索引 0.057s 后 O(1)。
2. `build_priority` 原三层嵌套（hosts×components×products）按 name/version 回查 findings，O(n³) 且有 display 名截断不一致隐患 → 改用 **line 行号关联**（scan_assets 里 host/product 都带 line，同一行归属），O(n) 建索引 + O(1) 查表。
3. `_chunked_extract` 冗余分支 + 死代码 `import itertools` → 精简为纯转发 `_structured_extract`。
4. `_fetch_rest` 原只 GET 一次、无分页 → 加分页支持（page/per_page 或 offset/limit 两种约定，逐页拉取到取空或 MAX_CI 顶）。

验证：独立自测 51 CVE/5 在野结果不变；10 万条 CI 端到端 2.3s 无退化；vLLM 的 CVE-2026-61732 正确命中（AI 框架领域覆盖）。语法校验 + 前端同步通过。

## CMDB 增加 SQLite 数据库直连模式（2026-10-05 凌晨）

用户有一套自建的 CMDB 测试数据集 `E:\cmdb\`（README 说明：35 表 / 152 万行 / 30.3 万 CI / 4 领域 FIN·ECOM·AI·SEC），核心是 `E:\cmdb\sqlite\cmdb.db`（722MB SQLite）。用户要把它接入平台做资产风险分析。

### 实现
- 后端 `cmdb_scan.py` 新增 `sqlite` 模式 + `_fetch_sqlite(cfg)`：连本地 SQLite 文件，自动抽取带 VERSION+HOST_IP 的「软件资产表」为扁平记录，复用 `_structured_extract`→`scan_assets` 流水线。
- `_SQLITE_TABLE_MAP` 定义 5 张表映射：middleware_instance(MW_TYPE/VERSION/HOST_IP/PORT)、database_instance(DB_TYPE)、bigdata_component(COMP_TYPE)、ai_model_service(FRAMEWORK/MODEL_VERSION/ENDPOINT)、app_instance(APP_NAME)。支持 tables 参数指定只抽某几张表。
- `_source_label()` 让报告来源显示"SQLite 数据库（cmdb.db）"。
- API 层 `handle_cmdb_scan_post` 加 sqlite 分支；前端加"数据库文件"tab + cmDbPath/cmDbTables 输入 + cmPane-sqlite。

### 实测
- `_fetch_sqlite` 抽 9.43 万条软件资产 0.3s；产品类型 4634 种（RabbitMQ/HAProxy/Kong/Nginx/Tomcat/Kafka/Spring Cloud Gateway…）。
- 完整流水线：9.43 万 CI → 6.57 万主机 + 2.39 万组件，命中 203 CVE（严重32 高危106），在野 2（CVE-2025-24813 Tomcat RCE、CVE-2024-38475 httpd），优先清单 14 条。
- 指定表 middleware_instance 单表 5 万 CI 仅 2.6s；Markdown 导出含全部章节。

### 关键坑（踩到并修复）
- **api.py 模式分支 bug**：`if mode=="sqlite"` 是独立 if 块，后面 `if mode=="rest" ... else: cfg["mode"]="inline"` 会把 sqlite 覆盖成 inline → 报"未提供 CMDB 数据"。修复：把 sqlite 挪进 `elif` 链（rest → sqlite → file → else inline）。
- 数据模型认知：这套 CMDB 是「五层 35 表规范化设计」，不是扁平资产清单；只有带 VERSION+HOST_IP 的表（中间件/数据库/大数据/AI模型/应用实例）才能映射到平台"软件资产分析"，纯基础设施表（机房/机柜/人员/合同）没有版本号不参与漏洞匹配。
- SQLite 路径在 bash heredoc 传参时反斜杠可能被吞，用正斜杠 `E:/cmdb/sqlite/cmdb.db` 最稳（sqlite3 能识别）。
