## 零、结论先行

**当前系统是「真实可用的 Agentic RAG」，不是 PPT 概念。** 但你这份验收框架里的 4 个章节，**没有一章能直接打"通过"**——原因不是功能缺失，而是**缺少验收框架要求的"证据物"**：覆盖矩阵、基准测试集、双盲标注规范、分项得分报告。

| 章节 | 现状定性 | 能否通过 |
|---|---|---|
| 1. 知识覆盖范围 | 数据源/本体齐全，**缺覆盖矩阵与更新指标** | 有条件通过 |
| 2. 复杂查询理解 | 9 类复杂查询大多有实现，**缺混淆矩阵与失败归因** | 有条件通过 |
| 3. 准确率≥95% + 推理链可解释 | 推理链格式已落地，**无基准集、无双盲评分、无法证 95%** | **不通过（缺证据）** |
| 4. 多跳推理 | 2-3 跳已实现且路径可展示，**缺多跳基准集与每跳证据核查** | 有条件通过 |

**总体结论：有条件通过。** 系统能力本身合格，但作为"可验收交付物"还差一份**基准测试集 + 双盲标注 + 分项得分报告**。以下逐章给出证据。

## 三、准确率 ≥95% 且推理链可解释

### 3.1 你的核心要求："必须拆开，不能混成一个指标"

这一条系统**在实现层面是对的**（结论与证据分离），但**验收层面不达标**。

**已实现（答案层/解释层结构）：**
- 结论与原始资料分离：`conclusion`（结论块）+ `evidence`（原始资料列表）
- 证据带来源/可信度/置信度：generator.py 输出 `数据来源 / 可信度 / 置信度`
- 引用可溯源：结论引用具体 CVE 编号，`evidence` 可点开看原文
- 推理链已落地：`reasoning_chain`（多跳每步的"检索式/派生依据/命中数"），前端可展开
- 正确拒答：`工具都没查到就直说"当前知识库没有相关情报"`（agent 系统提示词强制）

**未实现（验收证据物）：**
| 指标 | 你方标准 | 现状 |
|---|---|---|
| 事实型准确率 ≥95% | ❌ 无基准集 | **无法证明** |
| 开放分析型建议 ≥85-90% | ❌ 无评分 | **无法证明** |
| 引用可溯源率 ≥95% | ⚠️ 结构支持，未量化 | 需统计 |
| 幻觉率 ≤5% | ❌ 无标注 | **无法证明** |
| 正确拒答率 ≥90% | ⚠️ 有机制，未量化 | 需统计 |
| 推理链正确率 ≥85% | ❌ 无标注 | **无法证明** |
| 专家双盲评分（≥2人 + 一致性） | ❌ 无 | **未做** |

**本节的"不合格信号"命中（最严重）：** 需求方明确写了"准确率≥95%且推理链可解释"**不能混成一个指标**、必须有"测试集、评分规范、引用格式"。当前系统：
- ✅ 有推理链格式（结论→证据→推理步骤→来源→时间→置信度）
- ❌ **没有独立验证"推理链正确率"** —— 正如你指出的："引用一堆无关文档也算可解释，必须单独验推理链正确率"。这条**系统完全没做**。

## 四、多跳推理

### 4.1 跳数定义与实现

| 跳数 | 你的定义 | 系统实现 |
|---|---|---|
| 1跳 | 漏洞→影响资产 | ✅ `locate_assets` 工具 |
| 2跳 | 组织→常用漏洞→受影响资产 | ✅ 多跳迭代 + `get_related` |
| 3跳 | 组织→TTP→工具→IOC→资产 | ⚠️ 组织/TTP/工具可跳，**IOC 缺本体故第 4 跳断链** |

### 4.2 指标达标情况

| 指标 | 你方标准 | 现状 |
|---|---|---|
| 支持 2-3 跳 | ✅ | `MULTI_HOP_MAX_HOPS` + Planner-Executor |
| 每跳路径可展示、可点击溯源 | ✅ | `reasoning_chain` 前端展开 + `agent.trace` |
| 中间实体正确率 ≥85% | ❓ 未测 | 需基准集 |
| 多跳成功率 ≥85% | ❓ 未测 | 需基准集 |
| 路径可追溯率 100% | ⚠️ 结构支持，未量化 | 需验证 |
| 超跳数给部分结果不编造 | ✅ | agent 强制"工具里没有不许编" + 轮次上限 |

**已实现亮点：**
- 迭代多跳（2026-10-06 补）：第 N 跳检索式由第 N-1 跳结果派生，每步"派生依据"记入 chain——**这是真多跳，不是 fan-out**
- 无 Key/异常时退回模板路径，功能不降级

**缺口：** 没有专门构造的 2-3 跳问题集去验证"中间实体正确率"和"多跳成功率"。

## 六、结论与整改清单

**结论：有条件通过。**

系统是真实可运行的 Agentic RAG（8 工具编排 + 多跳 + 推理链 + 66,541 条语料 + 15s 实时流），不是"海量知识/多源融合"的空话。但作为验收交付物，**缺三样证据物**：

### 整改清单（按优先级）

**P0（验收前必须补，否则"准确率"相关全无法证明）：**
1. 建 **100-300 题基准集**，覆盖：事实 / 复杂（8类）/ 多跳（2-3跳）/ 拒答 / 权限 / 过期数据
2. 出 **双盲标注规范**（≥2 人，算 Cohen's Kappa 一致性）
3. 出 **分项得分报告**：意图识别 / 实体链接 / 查询改写 / 端到端正确率 / 幻觉率 / 拒答率 / 推理链正确率，**逐项分开报，不合并**

**P1（能力缺口）：**
4. **IOC 本体**：补 `ioc` 字段 + 威胁情报源（否则 IOC 时效、IOC 查询、"组织→TTP→工具→IOC→资产"第 4 跳全部断链）
5. 复杂查询的"比较/假设/否定"三类算子补强

**P2（可观测性）：**
6. 新增 `/api/qa/coverage` 接口：数据源→规模→最后同步时间，把"更新频率"从代码常量变成可查询面板
7. P95 响应时间盲测 + 红队测试报告
