## 二、执行摘要

### 2.1 总体结论

> **整体风险等级：高风险**。命中 7 项风险升级条件。

- 孤儿 CI 率 38.3%（> 20%）
- 配置漂移率 12.0%（> 5%），其中严重漂移 3222 条
- 流程外变更 4221 次（人工录入上线/下线/变更事件但未关联变更单）
- 敏感 API 无鉴权 1117 条 / 明文 HTTP 传输敏感数据 1720 条
- 管理岗未启用 MFA 290 人
- 严重（CVSS≥9.0）漏洞占比 19.6%
- 命中 CISA KEV 在野利用漏洞 4 个

**是否能导致数据泄露 / 权限绕过 / 数据被篡改 / 系统被接管**：

- 数据泄露：存在明确路径——6704 条漏洞记录位于互联网暴露面，其中 4 个漏洞已在野利用
- 权限绕过：存在——1117 条 API 无鉴权且标记为敏感，1720 条敏感数据以明文 HTTP 传输
- 数据被篡改：存在——配置漂移率 12.0%，其中严重漂移 3222 条，未经流程的变更 4221 次
- 系统被接管：风险高——125 条记录标记为已验证可利用（IS_VERIFIED_EXPLOIT）

**合规性判定**：不符合——互联网暴露面存在高危漏洞 6704 条；存在无鉴权敏感接口 1117 个 / 明文 HTTP 传输 1720 个；管理岗未启用 MFA 290 人；配置漂移率 12.0% 超 5% 阈值。详见第三、四、五章

> 判定口径：MFA 覆盖率 72.5%（管理岗未启用 290 人），API 鉴权率 83.3%，配置漂移率 12.0%。

```

     → 复测 → 通过则关闭 / 不通过则退回并升级 → 风险接受须书面审批
```

| 环节 | 责任方 | 留痕要求 |
| --- | --- | --- |

| 风险接受 | 业务负责人 | 书面审批（不接受默认关闭） |

- **不可定位记录 301 条**：其 CI_ID 指向软件包 / 补丁 / 工单的记录主键（SW- / PATCH- / ALERT- 前缀），且 CI_IP 列填的是端口号而非 IP，在 CMDB 里查不到对应机器，无法派单。它们仍计入漏洞总数，但不进资产风险排序。
- **位置覆盖率**：23997 / 28584 台资产可回溯到机房位置（84.0%）；其余为中间件/容器等经宿主二级解析仍无登记的记录，报告中标为「未登记」，不做推测。
- **机房位置口径（重要）**：资产的机房位置一律**以机柜 CAB_ID 的归属机房为准**，不采用资产表自带的 IDC_ID 列。实测该列与机柜归属在 8124 / 23997 条可定位资产上不一致（33.9%，物理机表层面更达 97.5% 仅 2.5% 吻合），而机柜表自身自洽（CAB_CODE 的城市前缀与其归属机房 CITY 吻合率 85.8%）——判定为 CMDB 资产表 IDC_ID 列未有效维护，而非个别资产登记错误。若强行采用该列，会输出「郑州第三数据中心 / AZ-兰州-13-A-57」这类自相矛盾的位置，运维无法据以找到机器。建议 CMDB 侧修复 IDC_ID 列后重新生成本报告。
- **严重度口径**：按 CVSS v3.1 官方区间由分值推导（9.0+ CRITICAL / 7.0+ HIGH / 4.0+ MEDIUM / 0.1+ LOW），不使用台账 SEVERITY 列的人工标签，避免出现「CVSS 10.0 却标 HIGH」的矛盾。CVSS 分值为 0 的记录（6010 条）按台账标签归入 INFO。
- **组件版本口径**：台账的 COMPONENT_VERSION / FIX_VERSION 为 CMDB 登记值，报告原样引用并逐条标注「→ 修复版本」；未做 CPE 区间二次匹配，修复前须以厂商公告核对（第四节已列出官方公告入口）。
- **不覆盖的范围**：本报告基于 CMDB 漏洞台账的**已登记**漏洞。未在台账中登记的组件漏洞（漏扫、漏登记）不在本报告范围内，需通过第四节的复扫动作持续补全。
- **数据处理**：全部解析与匹配在本机完成，CMDB 资产数据不外发、不联网。
