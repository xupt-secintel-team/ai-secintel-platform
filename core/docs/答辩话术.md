## 一、RAG 幻觉问题（必答题）

### Q1：你们的系统基于RAG，如何保证回答不产生幻觉？

**答：** 我们从四个层面系统性地解决RAG幻觉问题：

**第一，证据可信度分级。** 系统对每条情报按数据来源进行权威度分级：NVD、CISA KEV等官方机构来源可信度最高（95-100分），GitHub Advisory等厂商来源次之（75-85分），arXiv学术论文为学术研究级（70分），CSDN等社区来源最低（40-50分）。用户在界面上可以清楚看到每条情报的可信度标签，不会把社区文章当作权威结论。

**第二，多源交叉验证。** 系统自动对同一漏洞在不同独立数据源中的情报进行交叉比对。比如一个CVE漏洞如果同时在NVD、GitHub Advisory和CISA KEV三个独立来源中得到确认，标记为"多源交叉确认"；仅在单一来源出现的标记为"单源情报（待验证）"。这直接降低了单源错误或投毒内容误导用户的风险。

**第三，答案严格锚定检索证据。** 系统的智能答复不是让大模型自由生成，而是基于检索到的结构化情报字段（CVSS评分、CWE弱点、受影响组件、ATLAS攻击技术）进行模板化组织，每条结论都可以追溯到具体情报编号和原始链接。我们不做无证据的推断。

**第四，综合置信度量化。** 系统融合数据源可信度（权重50%）、交叉验证度（20%）、可利用性信号（15%）和情报时效性（15%），为每条情报计算0-100的综合置信度，让用户对情报可靠性有量化感知。

### Q2：如果检索到的文档本身被投毒了怎么办？

**答：** 这是RAG安全的重要问题，我们的防护包括：
1. **来源白名单机制**——知识库只从NVD、CISA、GitHub Advisory等经过验证的权威渠道采集，不接受任意用户上传文档；
2. **交叉验证天然抑制投毒**——攻击者需要同时污染多个独立数据源才能让虚假情报获得高置信度，成本极高；
3. **可信度标签透明**——即使单一来源被污染，其"单源情报"标签和低可信度评分会提示用户谨慎对待；
4. **数据安全知识库中专门收录了RAG投毒攻击与防护知识**（DSKB:AI04），系统自身也在持续监测这类风险。

### Q3：能演示一下可信度机制吗？

**答：** （演示路径）搜索一个关键词 → 结果卡片上展示可信度标签和交叉验证状态 → 点开详情 → 展示可信度评分明细、交叉验证来源列表、综合置信度 → 调用 /api/credibility 展示全局可信度分布统计。

## 二、语料来源问题（必答题）

### Q4：你们的语料数据从哪里来？是否合规？

**答：** 系统的语料全部来自公开、权威的安全数据源，共五大类：

| 数据源 | 性质 | 获取方式 |
|--------|------|---------|
| NVD（美国国家漏洞数据库） | 官方公开API | 官方API接口，遵守速率限制 |
| CISA KEV（在野利用目录） | 官方公开数据 | 公开JSON下载 |
| OSV/GitHub Advisory | 开源安全公告 | 公开API |
| arXiv | 学术论文 | 公开API |
| MITRE ATLAS | AI对抗知识库 | 公开知识库 |

所有数据均通过各平台官方公开API获取，严格遵守robots协议和速率限制（NVD无API Key时按6.5秒间隔请求），仅用于安全研究和防御目的。系统内置了数据来源与合规说明页面，每条情报都标注了原始来源和链接。

### Q5：为什么用国外的数据源？国内数据安全如何体现？

**答：** 两方面：
1. **NVD等是全球安全行业的基础设施性数据源**，漏洞编号（CVE）和评分标准（CVSS）是国际通用的安全语言，使用这些数据源符合行业惯例，且数据本身公开透明可审计；
2. **我们专门构建了数据安全特色知识库**（17条），覆盖《数据安全法》《个人信息保护法》、数据分类分级、数据脱敏、DLP、AI训练数据安全等中国数据安全法规和技术体系，这是我们参加数据安全大赛的特色模块。同时系统支持扩展国内数据源（如CNNVD、CNVD），架构上预留了采集适配器接口。

### Q6：数据量有多少？更新机制是什么？

**答：** （根据实际数据回答，参考：）语料库包含数万条漏洞情报、千余篇学术论文和数据安全知识库条目。系统设计了实时增量同步机制（monitor.py），支持按时间窗（默认6小时）自动从各数据源采集新增情报，采集完成后原子热切换检索引擎，不需要重启服务、不丢请求。也可以通过API手动触发同步。

## 三、主动漏洞挖掘能力问题（必答题）

### Q7：你们的系统能主动发现漏洞吗？还是只能检索已知漏洞？

**答：** 需要明确定位：**AI-SecIntel是一个安全知识情报系统，核心价值是情报的汇聚、关联、可信度评估和知识赋能，而不是自动化漏洞挖掘工具。** 这两者在安全运营体系中是互补关系：

1. **情报系统回答"已知什么"**——哪些漏洞已被公开、哪些正在被在野利用、攻击技术如何映射到MITRE ATLAS、修复措施是什么；
2. **漏洞挖掘工具回答"能发现什么"**——通过fuzzing、静态分析等手段发现未知漏洞。

但我们的系统在**主动安全能力**上做了三方面增强：
- **可利用性主动评估**：系统不只是收录漏洞，还基于KEV在野利用目录、Exploit-DB验证代码、GitHub PoC、补丁可用性等信号，为每条漏洞计算0-10的可利用性评分，主动帮助用户判断哪些漏洞最需要优先处置；
- **攻击链关联推理**：通过关系图谱把漏洞、CWE弱点、受影响组件、ATLAS攻击技术、战术阶段、缓解措施串联起来，用户可以从一个漏洞出发理解完整攻击路径，而不只是看到孤立条目；进一步支持 CTI 多跳关联与溯源归因；
- **架构上预留了主动扫描接口**，后续可以对接Nucleus等扫描器，将扫描发现的资产指纹与情报库自动匹配，实现"资产→漏洞→情报→处置"的闭环。

### Q8：那和普通的搜索引擎有什么区别？

**答：** 区别在五个方面：
1. **领域垂直**——只收录AI安全和网络安全情报，不是通用网页搜索；
2. **结构化富化**——每条情报经过CVSS评分、CWE弱点、ATLAS攻击技术、受影响组件等多维度结构化处理，支持精确筛选；
3. **可信度与交叉验证**——搜索引擎不对结果可信度负责，我们对每条情报做来源分级和多源验证；
4. **关系图谱与关联推荐**——能发现情报间的隐含关系（同组件、同弱点、同攻击技术），不是简单的关键词匹配；
5. **情报报告导出**——一键生成包含风险总览、重点情报、处置建议的完整报告，直接支撑安全运营决策。

## 四、多智能体决策闭环（决赛重点·必答）

### Q8.5：你们的六个智能体是怎么分工的？为什么不是单个大模型一把梭？

**答：** 六个智能体按「感知 → 编排 → 富化执行 → 研判 → 决策 → 质疑」分工，核心是**职责单一、全程留痕、可独立审计**：

| 智能体 | 职责 | 关键产出 |
| --- | --- | --- |
| ① 感知 | 监听情报流、按阈值筛候选 | 候选事件 + 筛选依据 |
| ② 编排 | 定优先级、限流分派、维护状态机 | 分派指令 |
| ③ 富化执行 | 资产定位 + POC 查询 | 富化结果（成败均记录） |
| ④ 研判 | 汇总证据、生成简报 | 结论 + 依据 + 处置建议 |
| ⑤ 决策 | 综合五维信号产出处置决策 | P0/P1/P2 决策卡 + XAI 推理链 |
| ⑥ 质疑 | 攻击者视角对抗审视、就地修正 | 抗辩结论 + 修正记录 |

**为什么不用单个大模型一把梭**：多智能体系统的最大风险是「黑箱」——出了问题不知道是哪一步错了。我们把链路拆成可审计的六段，`/api/ops/trace` 全程留痕（谁、何时、做了什么、成败、耗时），任一环节异常都能定位。而且这是**确定性规则驱动**，不依赖大模型 Key，可离线、可复现。

### Q8.6：决策智能体「效果显著」怎么量化证明？

**答：** 三层证据，都可现场复跑：

1. **端到端时效**：`POST /api/ops/decide_now` 从「发现漏洞」到「产出决策卡」全程 150ms 级（富化 127ms + 决策 23ms），全程无人干预；
2. **处置闭环自我进化**：回填记忆库落盘 `data/dispositions.json`，同一 CVE 再次出现时**秒判「已处置，无需重复研判」**；同组件其他漏洞决策时自动追加「另有 N 个同组件经验可参照」；
3. **红蓝自博弈修正误判**：质疑智能体命中盲区即就地修正——实测 CVSS 9.8 的漏洞若被误判 P1，会自动升档 P0 并补临时缓解动作。

三者的量化证据分别落在 `测试报告/决策智能体时效实测.md`、`tools/_test_decision.py`（12 项）、`tools/_test_disposition.py`（17 项）、`tools/_test_innovation.py`（20 项）。

## 五、技术实现类追问

### Q9：你们的检索算法是什么？为什么不用向量检索/大模型直接回答？

**答：** 我们采用**四层混合检索架构**：
- L1 词法层：BM25字段加权检索（标题、描述、组件等字段不同权重），保证精确匹配；
- L2 短语层：识别"prompt injection""model context protocol"等领域复合术语作为整体匹配，避免拆词导致的误匹配；
- L3 概念层：基于风险分类和同义词典构建概念向量，解决中英文语言鸿沟和术语变体问题（如"提示注入""prompt injection""jailbreak"的关联）；
- L4 重排层：融合AI产品识别、意图识别、字段偏好进行结果重排。

**为什么不全用向量检索：**
1. 漏洞编号（CVE）、组件名称（gradio版本）等需要精确匹配，向量检索在精确匹配上反而弱于词法检索；
2. BM25结果完全可解释（我们能展示每条结果的"命中原因"），向量检索的相似度是黑盒；
3. 零外部依赖、可离线部署，符合安全系统的自主可控要求；
4. 评测数据表明混合架构在P@5、nDCG等指标上表现优异（引用evaluate.py结果）。

### Q10：系统有什么技术亮点/创新点？

**答：** 六个亮点：
1. **情报可信度工程**——首次在安全情报检索中引入数据源分级、多源交叉验证、可利用性信号、时效衰减的四维置信度模型，直面RAG幻觉问题；
2. **MITRE ATLAS深度集成**——将AI对抗战术技术知识库与漏洞情报打通，支持从攻击技术到漏洞实例到缓解措施的全链路追溯；
3. **情报关系图谱 + CTI 多跳关联**——自动构建漏洞、弱点、组件、攻击技术、验证代码、缓解措施的多维关系网络；并支持以 CVE 为起点沿「组件→资产→攻击技术→战术」多跳游走，把同组件/同技术的相邻 CVE 一并关联，路径可解释；
4. **六智能体编排 + 处置闭环**——感知→编排→富化执行→研判→决策→质疑六个智能体事件驱动协作，决策智能体产出 P0/P1/P2 处置决策，质疑智能体红蓝自博弈就地修正误判；处置结果回填记忆库实现「同 CVE 秒判、同组件关联复用」的自我进化；
5. **溯源归因**——依据 CWE / KEV / 描述关键词把漏洞归因到威胁主体画像（勒索组织 / APT / 供应链投毒者）与 ATT&CK 战术链路，支撑从「发现」到「谁在打、打到哪一步」的研判；
6. **全领域覆盖+数据安全特色**——覆盖AI安全全栈（从提示注入到基础设施）并补充数据安全法规与技术知识库，支撑数据安全大赛主题。

### Q11：系统的准确率如何？有评测数据吗？

**答：** 我们构建了38条中英混合评测查询集，标准答案基于结构化字段（CPE精确匹配、CWE编号、描述命中）独立判定，避免自证循环。评测指标包括P@5、P@10、R@20、MRR、nDCG，并做了消融实验量化每一层检索架构的增益。（corpus生成后跑evaluate.py，引用实际数字）

零依赖设计使得系统可以在隔离网络环境中快速部署，不需要安装大量依赖包。

**答：**

### Q13.5：换一台机器（评委的笔记本 / 老系统 / 没装过环境）能跑起来吗？

**答：能，这是我们专门做过的一块，三条保证都有代码落点、有自测覆盖。**

1. **操作系统**：Windows 7 SP1 起、macOS 10.9 起、Ubuntu 14.04 起都能跑，
   三个系统各有一个双击入口（`启动服务.bat` / `start.command` / `start.sh`）。
   版本下限定在 Python 3.7——这是实测的，不是拍的：41 个文件用了
   `from __future__ import annotations`，富化模块用了 `dataclasses`，
   都是 3.7 才有的。3.7 上缺的 3.8/3.9 API 由 `core/compat.py` 兜底补齐。
   平台差异（端口排查命令 `netstat`/`lsof`/`ss`、长路径、编码）也收在同一个模块里，
   **全项目没有一处写死 Windows 命令**——这一点是踩过坑才补的。

2. **慢机器**：开机第一行就打印本机画像和档位，参数自动降，不需要人调。
   低配档（CPU≤2 核或内存<4GB）会把超时放大 2 倍、并发压到 2、
   关掉 torch 语义模型预热（省 470MB 内存和 16s 加载）、
   快车道从 15s 放宽到 60s、后台自动同步整个关掉。
   ——**"慢"不是问题，"慢得没有解释"才是**，所以我们让它开机就把话说清楚。

3. **没环境**：双击 `安装.bat`（或 `安装.command` / `安装.sh`），
   五步全自动：体检 → 建虚拟环境 → 探测最快的 pip 源 → 按档装依赖 → 自检。
   换机器实测 8 分钟内配置完成。首次双击启动脚本也会自动触发同一套流程。

4. **分发**：`tools/build_installer.py` 可打出约 1MB 的安装包，
   解压后就是三个系统的安装入口加一份安装说明，双击即可。
   语料 274MB 默认不打进包（打了之后压缩解压各要十几分钟，不划算），
   安装后联网抓取或拷现成的 `data/` 即可。

## 六、项目定位与团队类

### Q14：这个项目的目标用户是谁？解决什么痛点？

**答：** 目标用户是企业安全团队、安全运营中心（SOC）分析师和AI应用开发团队。痛点是：AI安全领域情报分散在NVD、学术论文、GitHub、社区文章等多个渠道，安全人员难以快速回答"我们用的AI组件有没有漏洞""这个漏洞是否正在被利用""该怎么修复"。AI-SecIntel通过情报汇聚、结构化富化、可信度评估和关联分析，提供一站式AI安全情报检索与决策支持。

### Q15：后续有什么迭代计划？

**答：**
1. 对接主动扫描器（Nucleus等）实现资产-情报自动匹配闭环；
2. 扩展国内数据源（CNNVD/CNVD）和威胁情报（ATT&CK通用）；
3. 引入向量检索作为语义召回补充（与现有词法检索混合）；
4. 多租户权限控制和知识库私有化部署；
5. 自动化漏洞验证（基于POC的安全验证沙箱）。
